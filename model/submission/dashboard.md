# Концепция дашборда «Продажи и исполнение заказов»

## Пользователь и решения

Руководитель маркетплейса оценивает, за счёт каких категорий и продавцов
меняются продажи. Руководитель операций видит отмены и нарушение обещаний
доставки. Аналитик проверяет полноту и противоречия данных перед выводами.

Дашборд отвечает на вопросы:

1. Продажи меняются из-за количества заказов или среднего чека?
2. Какие продавцы и категории обеспечивают товарный оборот?
3. Какие регионы покупателей чаще сталкиваются с просрочкой?
4. На какие показатели могут влиять пропуски и несогласованные данные?

Это концепция; интерфейс по заданию реализовывать не требуется.
Показатели доступны на историческом снимке 2016–2018, а не в реальном времени.

## Период и общие определения

Основной фильтр периода — `orders.purchased_at >= начало AND < конец`.
Месяцы группируются по дате оформления заказа. Это анализ когорт оформления
по их состоянию в выгрузке, а не помесячный бухгалтерский учёт поступлений.
Дата фактической доставки используется только в явно подписанном режиме
«доставлено за период», который нельзя смешивать с когортным режимом.

`delivered` — правило состоявшейся продажи для кейса. Отсутствие даты
вручения не удаляет такой заказ из выручки; для метрик сроков нужна сама дата.
Денежная единица — единица источника; конвертация валют не выполняется.
Подпись «Выручка кейса / товарный оборот» отличает стоимость товаров
от комиссионного дохода маркетплейса: ставки комиссии в данных отсутствуют.

## Показатели и источники

| Показатель | Формула | Уровень и источник | Правила и ограничения |
|---|---|---|---|
| Товарный оборот | `SUM(price)` доставленных позиций | Единица товара; `mart.delivered_items` | Без доставки; категория без названия сохраняется |
| Оформленные заказы | `COUNT(DISTINCT order_id)` всех статусов | Заказ; `core.orders` | Включает отменённые и незавершённые; отдельная метрика |
| Доставленные заказы | `COUNT(DISTINCT order_id)` при `is_delivered` | Заказ; `mart.order_totals` | Когорта по дате покупки, статус на момент выгрузки |
| Средний чек | `SUM(order_amount) / COUNT(order_amount)` при `is_delivered` | Сначала сумма позиций с доставкой по заказу; `mart.order_totals` | Нет позиций — сумма неизвестна; число таких заказов выводится отдельно |
| Доля отмен | `COUNT(заказы status_code='canceled') / COUNT(все оформленные заказы)` | Заказ; `core.orders` | `unavailable` отдельно, не подменяет canceled; не прогноз будущих отмен |
| Просроченная доставка | `COUNT(delivered_date > estimated_date) / COUNT(доставленные с обеими датами)` | Заказ; `mart.order_totals` | Сравнение календарных дат, не timestamp с обещанным временем 00:00 |
| Покрытие дат доставки | `COUNT(доставленные с обеими датами) / COUNT(все delivered)` | Заказ; `mart.order_totals` | Обязательный спутник доли просрочек; показывает исключённые пропуски |
| Заказы с расхождением оплаты | `COUNT(DISTINCT order_id)` для `payment_amount_mismatch` | Заказ; `mart.quality_issues` | Порог `ABS(позиции с доставкой − платежи) > 0,01`; только заказы с обеими суммами |

Все доли отображаются в процентах; пустой знаменатель даёт NULL/«нет данных»,
а не 0%. Разницы денежных сумм сравниваются в точном `numeric`.
Отсутствующие данные не превращаются в доказанные нули.

## Срезы и правила фильтрации

Основные срезы: месяц покупки, штат покупателя, продавец, категория.
География покупателя берётся из `customer_order_profiles` конкретного заказа;
география продавца — из `sellers`. В интерфейсе они подписаны раздельно.

- По продавцу/категории оборот включает только подходящие позиции.
- Число заказов при таком фильтре — distinct заказы с подходящими позициями.
- Общий средний чек, доля отмен и доля просрочек находятся в блоке «Заказ
  целиком» и фильтруются периодом и географией покупателя. Фильтры категории
  и продавца действуют только на блок «Позиции», что явно подписано рядом
  с фильтрами. Это не позволяет выдавать сумму выбранной части за полный чек.
- Заказы без позиций видны в общих метриках заказов и диагностике, но нельзя
  уверенно отнести их к продавцу или категории.
- Срок доставки доступен для заказа целиком. В мультипродавцовом заказе
  нельзя приписывать задержку конкретному продавцу без данных об отправлениях.

## Что нельзя складывать

| Метрика | Почему сумма по срезам неверна | Как пересчитать итог |
|---|---|---|
| Средний чек | Группы имеют разные размеры | Сумма сумм заказов / число заказов |
| Доли отмен и просрочек | Разные знаменатели | Сложить числители и знаменатели непересекающихся групп, затем разделить |
| Уникальные покупатели | Один человек встречается в разных периодах и категориях | `COUNT(DISTINCT customer_unique_id)` заново на общем наборе |
| Число заказов по продавцам/категориям | Один заказ может попасть в несколько групп | `COUNT(DISTINCT order_id)` на общем наборе |
| Число проблемных заказов по кодам качества | Один заказ имеет несколько проблем | `COUNT(DISTINCT order_id)` после фильтрации диагностик заказов |

Товарный оборот и число единиц аддитивны по непересекающимся позициям.
Для месячных когорт один заказ относится к одному месяцу, но один покупатель
может относиться к нескольким месяцам.

## Форма экрана

1. Вверху: период, штат покупателя, время обновления снимка и подпись даты
   группировки. На текущем этапе нет журнала сборок: время обновления должно
   появиться из будущего журнала, его нельзя подменить временем открытия экрана.
2. Блок «Заказ целиком»: KPI оформленных и доставленных заказов, среднего чека,
   отмен, просрочек и покрытия дат. Временной график объёма и среднего чека —
   две согласованные панели с отдельными шкалами, без скрытой двойной оси.
3. Блок «Позиции»: фильтры продавца/категории, месячный оборот и таблицы лидеров.
   В таблице — исходный код категории, перевод/отображаемое имя, сумма и доля.
4. Блок качества: число записей без категории/дат, расхождения оплаты,
   переход к списку идентификаторов и пояснениям.

Пустые месяцы сохраняются календарём. Нулевые продажи отображаются как 0;
средний чек без заказов — «нет данных».

## Границы интерпретации

Нет событий посещения и корзины — нет конверсии из посещения в покупку.
Нет комиссий, себестоимости и возвратов — нет прибыли и чистого дохода.
Нет истории статусов — нет достоверного состояния заказа «на конец месяца».
Повторные оформления из задания не равны повторным успешным покупкам.
Разница метрик между группами не доказывает причинное влияние продавца.
Свежие когорты незавершённых заказов нельзя сравнивать с завершёнными
старыми когортами без оговорки о разном времени наблюдения.

# Ответы на вопросы аналитиков

Запросы — в [answers/](../answers/), все считаются из витрин `mart`,
не из `raw` (это проверяет тест). Проверенный эталон исходной выгрузки —
в [artifacts/answers/](../artifacts/answers/). Новый комплект создаётся командой
`docker compose run --rm app answers` в `artifacts/runtime/answers/`.

Посмотреть результат одного запроса:

```bash
docker compose run --rm app sql answers/01_monthly_revenue.sql
```

Сверка всех ответов с контрольными цифрами: `docker compose run --rm app check`.
Все 10 контрольных значений совпадают; при расхождении команда падает с ошибкой.

## Общие определения

| Термин | Определение |
|---|---|
| Выручка | Сумма `price` позиций доставленных заказов, без стоимости доставки |
| Средний чек | Сумма `price + freight_value` заказа, усреднённая по доставленным заказам |
| Покупатель | Человек, `customer_unique_id` |
| Месяц | Месяц оформления заказа |
| Срок доставки | Календарные дни от оформления до вручения, только при известной дате вручения |
| Опоздание | Вручение позже обещанной даты (сравниваются даты) |

## 3. Средний чек

| Средний чек | Строк в заказе | Единиц в заказе |
|---:|---:|---:|
| **159.88** ✓ | 1.0385 | 1.1422 |

Строка чека — товар одного продавца в заказе. Единица — одна строка
`order_items`. Единиц больше, чем строк: иногда покупают несколько
одинаковых товаров.

Задание просит два числа, чтобы проверить уровень расчёта. Если считать
строкой чека строку `order_items`, оба числа совпадут (1.1422 и 1.1422,
так было в первой версии `main`), и проверка ничего не покажет.

## Сохранение комплекта ответов

```bash
docker compose run --rm app answers
docker compose run --rm app answers --output-dir artifacts/runtime/custom_answers
```

Каталог по умолчанию — `artifacts/runtime/answers/`. В нём:

```text
current.json                     указатель на последний опубликованный комплект
generations/<export_id>/
  01_monthly_revenue.csv          CSV с ответами на вопросы 01–10 (09 — два файла)
  ...
  results.json                   те же результаты в JSON
  sql/                           точные SQL-тексты выполненных запросов
  manifest.json                  контекст, состав и SHA-256 файлов
```

Команда сначала проверяет наличие всех пяти SQL-файлов, затем получает данные
и контекст в одной `REPEATABLE READ READ ONLY` транзакции. Аналитические SQL
читают `mart`; исходный `raw` читается отдельно только для отпечатка происхождения.
CSV/JSON/SQL записываются во временный каталог. После полной подготовки
он становится неизменяемым поколением; атомарная замена `current.json` публикует
весь комплект. Ошибка до этой замены оставляет прежнее поколение действующим.
После публикации ответы показываются в терминале из сохранённого снимка,
без повторного запроса к модели.

Читатель открывает `current.json` один раз и использует относительный путь
из поля `generation`. Нельзя заново выбирать текущий комплект для каждого CSV:
между такими чтениями может завершиться следующая выгрузка. Старые поколения
автоматически не удаляются. При отказе переключения указателя может остаться
готовый, но неопубликованный каталог; он не считается текущим.

Manifest формата 1 содержит время UTC, ID выгрузки, количество/типы колонок,
число строк, текст и SHA-256 каждого SQL, размеры/хеши выходных файлов.
`current.json` содержит SHA-256 самого manifest. Контекст:

- `publication`: ID, отпечаток входа/преобразования, источник, номер, тип
  (`synthetic`/`external`) и время текущей публикации. `null` после первичной
  сборки из исходного `raw`. Читается в той же транзакции, что и ответы.
- `raw` и `core`: SHA-256 содержимого каждой таблицы и всей схемы, включая
  служебные поля происхождения; строки упорядочены перед хешированием.
- `model_schema_sha256`: отпечаток реально созданных колонок, ограничений,
  индексов, представлений и функций `core`/`mart`.
- `workspace_model_sha256`: отдельный отпечаток локальных SQL-файлов модели.
  Изменённый файл без `build` не выдаётся за применённую ревизию БД.

Это снимок наблюдаемого состояния `raw`/`core`, а не журнал загрузок и сборок.
Отдельная история публикаций модели этим manifest не создаётся.
Она ведётся загрузчиком в `ops.dataset_versions`; подробнее —
[приём новых снимков](ingestion.md).

Деньги остаются точными: десятичные строки в JSON, исходная точность в CSV.
CSV используют UTF-8 и LF. Получение полного отпечатка читает таблицы целиком:
стоимость этой операции учитывается при росте объёма. Эталонные CSV в корне
`artifacts/answers/` команда не перезаписывает; новые runtime-результаты исключены из Git.

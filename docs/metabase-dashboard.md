# Дашборд аналитика в Metabase

Исходники: `metabase/questions/*.sql`. Скрипт `scripts/create_metabase_dashboard.ps1`
создаёт отдельную коллекцию и девять карточек в Metabase: три KPI, два графика,
продавцы, категории, детали заказов и качество данных.

## Запуск

В корне проекта запустить Docker Desktop, затем:

```powershell
docker compose up -d postgres metabase
```

Если данные ещё не загружены и модель не собрана:

```powershell
docker compose run --rm app setup
docker compose run --rm app build
docker compose run --rm app check
```

Открыть http://localhost:3000, создать администратора и добавить Marketplace:
PostgreSQL, сервер `postgres`, порт `5432`, база `marketplace`, пользователь
и пароль `hack`. Дождаться синхронизации структуры.

В PowerShell запустить:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/create_metabase_dashboard.ps1
```

ExecutionPolicy применяется только к этому процессу. Скрипт спросит email и
пароль в системном окне; не сохраняет пароль в файлы. Если автоматический поиск
источника не сработал, указать `-DatabaseId N`, где N — ID Marketplace из URL
его настроек. `-Url` позволяет указать другой адрес Metabase.

Повторный запуск останавливается, если коллекция уже существует, чтобы не
перезаписать пользовательские изменения. При частичной ошибке созданная
коллекция и завершённые карточки остаются: проверить их в интерфейсе перед
повторной установкой. Скрипт не создаёт администратора и не меняет модель БД.

## Чтение и фильтры

- Дата с / дата по включительны; обе относятся к оформлению заказа.
- Без дат используются все доступные данные. Штат — код покупателя, например SP.
- Карточки, графики, категории, продавцы и детализация используют одинаковые фильтры.
- Оборот — товары без доставки; средний чек — товары с доставкой.
- Средний чек AVG пропускает неизвестные суммы; пустое значение не заменяется нулём.
- Календарь сохраняет месяцы без продаж в пределах календаря модели.
- Категории используют актуальный `category_key` и имена из `core.categories`.
- Качество относится ко всему набору, отдельно от фильтров продаж. Количество
  проблем не равно количеству заказов; сущности считаются внутри типа и кода.
- Топ-10 продавцов не обязан суммироваться до полного оборота.
- Таблица деталей предназначена для проверки заказов и выгрузки средствами Metabase;
  лимиты отображения/выгрузки определяются настройками сервера.

## Проверка после установки

1. Без фильтров сопоставить оборот с SQL команды и суммой всех категорий/месяцев.
2. Выбрать 2017-01-01 — 2017-12-31 и SP: проверить согласованность продажных блоков.
3. Выбрать период без данных: количество/оборот — 0, средний чек пустой.
4. Сбросить фильтры; убедиться, что качество не меняется от периода продаж.
5. Открыть детали нескольких заказов и сопоставить товары, доставку и сумму чека.

Статус: исходники подготовлены по текущей модели; выполнение SQL и API требует
работающего PostgreSQL и Metabase и должно быть проверено при первом запуске.
API Metabase не версионируется; при несовместимости смотреть `/api/docs/` сервера.

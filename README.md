# RWB Marketplace Model

Решение кейса хакатона RWB «Модель маркетплейса: от корзины до выкупа».

**Репозиторий команды:** [L3iHS/RWB-marketplace-model](https://github.com/L3iHS/RWB-marketplace-model).

**Задание и окружение организаторов:** [daniilivanovp-droid/hackathon-students](https://github.com/daniilivanovp-droid/hackathon-students).

## Цель

Построить модель данных маркетплейса Capibara, на основе которой аналитики смогут получать согласованные и проверяемые показатели продаж, покупателей, продавцов и исполнения заказов.

Исходные данные — восемь выгрузок [Olist](https://github.com/olist/work-at-olist-data), 550 759 строк за 2016–2018 годы. Использование датасета регулируется лицензией CC BY-NC-SA 4.0, указанной организаторами.

## Архитектура

- `raw` — исходные данные без изменений; все поля загружаются как текст.
- `core` — типизированная модель с явными ключами, связями и уровнем детализации.
- `mart` — аналитические представления и расчёты на основе модели.

Основной стек — PostgreSQL 16 и SQL. Python используется для загрузки, диагностики и проверок. Локальное окружение запускается через Docker Compose.

## Результат проекта

- Воспроизводимая SQL-сборка модели из `raw`.
- Ответы на вопросы аналитиков и полученные значения.
- Проверки качества данных, бизнес-правил и повторной сборки.
- Описание модели и краткая записка о принятых решениях.
- Концепция дашборда «Продажи и исполнение заказов».
- Стратегия развития модели и технологического стека.

## Структура

```
explore/   запросы для разведки данных, в сборку не входят
model/     SQL-скрипты, собирающие схему core из raw (выполняются по порядку имён)
docs/      находки по данным, записка о решениях, дашборд, стратегия
build.sh   сборка модели с нуля одной командой
```

## Сборка модели

Окружение (PostgreSQL + сырые данные в схеме `raw`) поднимается из репозитория
организаторов командой `bash scripts/setup.sh`. После этого:

```bash
bash build.sh
```

Скрипт по порядку выполняет все `model/*.sql` в контейнере `hack_postgres`
и останавливается на первой ошибке. Схема `core` пересоздаётся с нуля,
`raw` не меняется.

Выполнить отдельный файл, например разведку:

```bash
bash build.sh explore/01_profiling.sql
```
